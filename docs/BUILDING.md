# 构建 v0.3.4

本仓库不携带工具二进制、运行时缓存、签名证书或用户档案。普通运行按 README 安装锁定 npm 依赖即可。安装包构建沿用 Electron 45.2.1、@electron/packager 20.3.0、已有 NSIS Unicode 工具集。

1. 从 Electron 官方 v45.2.1 Release 准备 `electron-v45.2.1-darwin-arm64.zip`、`electron-v45.2.1-darwin-x64.zip`、`electron-v45.2.1-win32-x64.zip`，按官方 `SHASUMS256.txt` 核对，存入同一缓存目录。
2. 在 macOS 上设置 `WONANGFEI_ELECTRON_ZIP_DIR` 为该目录的绝对路径；依次执行以下命令。脚本从 package.json 读取版本，仅复制 src、desktop 与最小 package.json，不包含数据或测试。

```sh
node scripts/build-release.mjs mac-arm64
node scripts/build-release.mjs mac-x64
node scripts/build-release.mjs windows-x64
node scripts/build-dmg.mjs arm64
node scripts/build-dmg.mjs x64
```

Mac 构建需要系统 codesign、ditto、hdiutil；仅 ad-hoc 临时签名，不自动申请证书、公证或更改系统安全设置。输出在 `dist-release/v0.3.4/`，已存在的产物拒绝覆盖。

Windows 安装器由 `node scripts/build-nsis.mjs` 制作，需要事先准备 `.installer-tools/nsis-bundle/makensis` 及配套目录。本轮复用已验证来源的 electron-builder 工具集 NSIS 3.12（nsis@1.2.1），来源校验记录对应 app-builder-lib 26.18.0 的官方 toolset 清单；仓库不自动下载或安装这些工具。安装器为 x86 Unicode 引导，内含 x64 App，要求 Windows 10 x64，只按当前用户安装，不要求管理员权限。卸载按明确文件清单删除应用，保留 AppData。

`release-smoke.cjs` 用于打包后验收。指定全新的 `WORKDAY_DATA_DIR`、`WORKDAY_EVIDENCE_DIR`、`WORKDAY_SMOKE_SCRIPT` 后，以 `--smoke-test` 启动 App。Mac 在外置卷上读取外部测试脚本时可能等待文件访问授权；可把测试脚本及输出放到内部 `/tmp`，不需要改安全设置。不要让测试使用真实档案。不能把 `open` 的退出码当验收结果，应检查生成的 JSON 报告。

新应用图标已经包含 ICNS、ICO、PNG，构建无需参考效果图。两个 Mac App 和 Windows App 的 app.asar 哈希一致，公开源码的 src/desktop 与包内逐文件一致。

## 本轮打包验收

Use release-smoke.cjs with WORKDAY_RELEASE_PHASE=calendar or salary, a new WORKDAY_DATA_DIR and WORKDAY_EVIDENCE_DIR for each run. Never use a real profile. Test the application copied from the final DMG through LaunchServices; this does not claim a physical Finder click or downloaded Gatekeeper approval. upgrade-smoke.cjs expects an isolated baseline generated by the actual old release model. Package and test scripts are excluded from app.asar.
