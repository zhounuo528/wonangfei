# 网页 0.4.8 部署交接

源码位于仓库 web/，Node.js 22.12+，无前端 npm 依赖。源码部署 Root Directory=web，执行 npm run build，输出 dist，使用 web/vercel.json。

静态 ZIP 的根目录已经是 36 个页面资源（含 index.html、构建版本模块和 version.json）、静态 vercel.json 和 BUILD-MANIFEST.json。静态配置不包含源码构建步骤，不要与 web/ 源码构建配置混用。部署包的提交、准确路径和 SHA-256 由本次独立交接记录提供，不能使用之前的 -dev 包替代。

## 当前范围

本轮提交源码，生产发布由部署负责人执行；本轮不访问 Vercel、不修改 DNS、不直接联系或替代交接人。部署方核对原项目与域名、提交及包 SHA-256，先记录原生产部署/回滚 ID，再预览验收，最后提升生产。不要因权限不足改用另一团队、项目或域名。

## 数据和回退

数据库名和数据库版本仍为 wonangfei-web-v1 / 1，个人记录内容格式支持 1/2/3/4。旧档案不会自动推断首次零工资；已有排除旧加班费的策略会迁移到格式 3 并限定旧费用 ID。首次工资、日期调薪和普通补班整月重分也使用格式 3，保留修改日志。新代码兼容旧数据，单日临时花销与固定负担修改采用格式 4；旧版 0.4.4／桌面 0.3.4 不支持格式 4，之前旧版也不支持后续新增格式；旧桌面读到新数据后锁定且不能覆盖原文件。

上线前在原域名导出升级前 JSON 备份，保留当前部署 ID 和旧构建。静态资源回滚不会回滚 IndexedDB；旧版回退必须配合升级前备份，或优先用兼容的向前修复。不得清空站点存储、强改内容格式号或把新备份强行导回旧版。不自动合并旧演示槽与个人数据，也不更换 origin。

历史时段/加班费/摸鱼和已完成目标结算保留；请假/调休归档原工时，补薪明确选择，普通补班重分整月自动工资，手动例外和原费用快照保留。过去没有实际记录的日期不造满勤或收益，未来只安排计划。历史修正重算目标池，可能变负，原结算不撤销或重复。

## 发布后验收

核对线上提交、index.html、model.mjs、calendar.mjs、time-editor.mjs 和样式等全部资源哈希，确认原域名 HTTPS/重定向、CSP、nosniff、referrer 和缓存响应头，防止旧新模块混用。

使用独立虚拟档案检查首次设置、任意日期改薪、按设定开始补算/午休/封顶、返工/跨日、进行中补填实际下班、多行时间直接编辑、原加班费和摸鱼保留、历史请假/撤销/补录、未来排班、无薪休息日加班稀释均薪、日历净利润/隐藏/窄屏、目标/周报/月报、备份往返及并发写保护。生产实测完成前不要宣称已上线验收；本机 Chromium 通过不等于 Safari、Firefox 或实体手机通过。


## 关于版本和检查更新

网页 0.4.8 从构建生成版本模块和同源 `version.json`；待部署包必须在干净的固定提交上重新构建，确认 `sourceCommit` 与交接提交一致、`development=false`。源代码直读缺少生成文件不能当作可交付构建。网页检查不使用桌面 GitHub 版本号，CSP meta 和响应头均仅从 `connect-src none` 放宽为 `self`；`version.json` 设置 no-store。部署后核查该文件 JSON、版本、revision 与页面模块一致，测试当前版／新版／旧站点或离线错误，以及未保存设置阻止刷新。

新增统一日期修改时，默认不补扣原本未计入的历史固定负担。主动勾选会列出历史分摊或按当前项目计算的金额，再保存为当日快照；不重写其他日期。格式 4 的记录不能直接回到 0.4.4，先保留升级前和升级后备份，优先兼容的向前修复，不清空 IndexedDB 或强改格式号。

网页版手动检查只发固定的同源 GET，无 Cookie、Referrer、参数或账本内容；所有业务记录仍在本地。初次页面加载只读取正常静态模块，不自动发起版本检查。发布目标、原域名和线上响应头要由部署负责人实际核验；本轮不部署、不联系交接人。
