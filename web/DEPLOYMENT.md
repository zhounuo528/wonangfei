# 网页 0.4.3 部署交接

源码位于仓库 web/，Node.js 22.12+，无前端 npm 依赖。源码部署 Root Directory=web，执行 npm run build，输出 dist，使用 web/vercel.json。

静态 ZIP 的根目录已经是 index.html、28 个静态资源、静态 vercel.json 和 BUILD-MANIFEST.json。静态配置不包含源码构建步骤，不要与 web/ 源码构建配置混用。部署包的提交、准确路径和 SHA-256 由本次独立交接记录提供，不能使用之前的 -dev 包替代。

## 当前范围

本轮提交源码，生产发布由部署负责人执行；本轮不访问 Vercel、不修改 DNS、不直接联系或替代交接人。部署方核对原项目与域名、提交及包 SHA-256，先记录原生产部署/回滚 ID，再预览验收，最后提升生产。不要因权限不足改用另一团队、项目或域名。

## 数据和回退

数据库名和数据库版本仍为 wonangfei-web-v1 / 1，个人记录内容格式支持 1/2。旧个人数据加载后保持格式 1，第一次保存新的日历/时间修正才升级为 2，并记录修改前后快照。新代码兼容旧数据，旧版 0.4.2 的模型及备份解析器明确拒绝格式 2；旧桌面读到新数据后锁定且不能覆盖原文件。

上线前在原域名导出升级前 JSON 备份，保留当前部署 ID 和旧构建。静态资源回滚不会回滚 IndexedDB；旧版回退必须配合升级前备份，或优先用兼容的向前修复。不得清空站点存储、强改内容格式号或把新备份强行导回旧版。不自动合并旧演示槽与个人数据，也不更换 origin。

历史时段/加班费/摸鱼和已完成目标结算保留；请假/调休归档原工时，补薪明确选择，基础计薪分母不重分。过去没有实际记录的日期不造满勤或收益，未来只安排计划。历史修正重算目标池，可能变负，原结算不撤销或重复。

## 发布后验收

核对线上提交、index.html、model.mjs、calendar.mjs、time-editor.mjs 和样式等全部资源哈希，确认原域名 HTTPS/重定向、CSP、nosniff、referrer 和缓存响应头，防止旧新模块混用。

使用独立虚拟档案检查首次设置、今天/明天改薪、按设定开始补算/午休/封顶、返工/跨日、进行中补填实际下班、多行时间直接编辑、原加班费和摸鱼保留、历史请假/撤销/补录、未来排班、无薪休息日加班稀释均薪、日历净利润/隐藏/窄屏、目标/月报、备份往返及并发写保护。生产实测完成前不要宣称已上线验收；本机 Chromium 通过不等于 Safari、Firefox 或实体手机通过。
