# 网页 0.4.2 部署交接

源码位于仓库 web/，Node.js 22.12+，无 npm 依赖。源码构建使用 web/vercel.json：项目 Root Directory 为 web，npm run build，输出 dist。独立静态 ZIP 的根目录已是 index.html、23 个资源及静态 vercel.json，不再执行源码构建；两类配置不要混用。

## 当前状态与范围

本轮只提交源码及静态包，线上仍待部署方执行。本轮未访问或重试先前受限的 Vercel 项目操作，未修改域名或 DNS。之前目标是 Shuke / wonangfei-web，但当前生产部署 ID、域名与权限由部署方现场确认，不能把历史 404/403 当作本轮状态。

发布方先核对提交、包 SHA-256 和现有项目/域名，记录当前生产部署及可回滚 ID；先预览验收再提升生产。不要因权限不足改用别的团队、项目或域名。

## 数据和回退

数据库名和版本仍是 wonangfei-web-v1 / 1，个人槽及修订格式不变，不清除站点存储。演示槽留在原处，只读取个人数据；旧演示备份拒绝导入。旧个人备份保持兼容，含旧工资快照、成本分摊、目标结算及 demo:null。首次使用工资为空，原数字不会被自动转成税前/税后口径。

工资今天/明天生效随 salaryChanges 持久保存；今天重估不改旧日期和额外加班费，目标从账本重算，旧完成结算不撤回。已记录日期不会因新默认补算自动变化。

发布前在原域名导出升级前个人备份。数据归当前浏览器 origin，改变域名不会自动带走数据。静态文件回滚不回滚 IndexedDB。旧 0.4.1 不理解未来生效工资，旧 0.4.0 还不接受自动零工作日；不要导入新备份到旧版后继续记账。出现问题优先兼容的向前修复，确需恢复旧版时配合升级前备份；不得用清空站点存储替代回退。也不要自动合并旧演示与个人档案。

确认线上提交、资源哈希、原域名 HTTPS/重定向和 CSP 等响应头；在隔离虚拟档案检查首次设置、五种考勤、今日/明日改薪和重启、补算/午休/下班封顶/返工/重叠、成本/摸鱼/目标/总结/月报、备份往返、旧演示迁移、多标签页保护和手机视口。不要读取真实财务数据。本机 Chromium 检查通过不等于 Safari、Firefox、实体手机或生产实测。
